# Synap Core: agent rules (single-file edition)

Copy this file alone into `AGENTS.md`, `.cursor/rules/synap-core.mdc` or `.clinerules`. The full skill (`npx skills add maximem-ai/maximem_synap_core --skill synap-core -y`, or the `skills/synap-core/` folder of https://github.com/maximem-ai/maximem_synap_core) has more detail, the scripts, and wins.

Synap Core is the open-source, self-hosted edition of Maximem Synap's memory engine: eight Docker services, API on `127.0.0.1:8000`, data in Docker volumes, same SDKs as Synap Cloud, **no API key**. Your job: take the human from nothing to a **verified, running** server. For the hosted Synap Cloud, use the `synap` skill instead.

**Conventions.** `<folder>` is the Synap Core folder (the one that contains `deploy/`). **Each shell call starts fresh**, so an `export` or `cd` does not carry over: put these prefixes in the SAME command as every `docker compose`: on **Linux** `SYNAP_USER=$(id -u):$(id -g)`; on the **published-image path** `SYNAP_IMAGE=ghcr.io/maximem-ai/maximem_synap_core:<tag> SYNAP_PULL_POLICY=always`. `<compose>` below means `docker compose -f deploy/docker-compose.yml` run from `<folder>` with those prefixes. The helper scripts are in the repository under `skills/synap-core/scripts/` (so they exist on the clone path); without them, do the same steps by hand as written. Run long commands in the BACKGROUND with output to a file and read the file; a call that blocks for more than about ten minutes is cut off.

**Never guess. If anything is unclear, stop and ask. One question at a time; each carries your recommendation and a tip (what the answer changes). Never ask the human to paste a key into chat. Never print, echo or commit a key or token (never `cat .env`).**

## The steps

1. **Check the machine yourself** (no clone yet): `docker --version`, `docker compose version` (v2 needed), `docker info --format '{{.MemTotal}}'` (Docker needs 6 GiB or more), free disk 8 GiB or more, port 8000 free (`lsof -i :8000` or `docker ps --filter publish=8000`), `docker volume ls | grep synap-core_` and `docker ps -a | grep synap-core-` (an earlier install: a new start REUSES those volumes, old memories and scoping included; ask keep or fresh; never delete without an explicit yes). Linux: `SYNAP_USER=$(id -u):$(id -g)` in front of every `docker compose` command. Windows: WSL2 only. After cloning, `python3 skills/synap-core/scripts/preflight.py` does all of this.
2. **Ask where it lives and which path.** Clone (recommended): `git clone https://github.com/maximem-ai/maximem_synap_core <folder>`. Published image: `ghcr.io/maximem-ai/maximem_synap_core:latest` (or a tag like `:0.1.0`); download `deploy/docker-compose.yml`, `config/memory.yml` and `.env.example` from the repo's raw URLs into `deploy/`, `config/` and the folder; every Compose command then needs `SYNAP_IMAGE=<image> SYNAP_PULL_POLICY=always` in front. If the image pull says `unauthorized`, the package is still private: use the clone.
3. `cp -n .env.example .env && chmod 600 .env` (`-n`: an existing `.env` is never replaced; on the image path download a file only if it is missing). **Never open, read, grep or print `.env` or the output of `docker compose config` with any tool.**
4. **Scoping (final after the first memory):** consumer app = `equals_customer` (calls carry a user id only; the default in `config/memory.yml`); business app = `strict` (a customer id AND a user id on every call): `cp config/samples/business-app.yml config/memory.yml` BEFORE the first start.
5. **Model.** `SYNAP_LLM_PROVIDER` is `openai`, `anthropic`, `ollama` or `openai-compatible`; `SYNAP_LLM_MODEL` is the exact model name; the key line is `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `SYNAP_LLM_BASE_URL` + `SYNAP_LLM_API_KEY` (Gemini: provider `openai-compatible`, base URL `https://generativelanguage.googleapis.com/v1beta/openai/`). One model does every step; there is no default. Ollama on Linux must listen on an address the container can reach. Write `.env` only through `skills/synap-core/scripts/set_env.py KEY=VALUE` for non-secret lines, or tell the human which lines to type (without the script they type all of them). The key: ask "was this agent started from the terminal where you exported it?"; if yes, `set_env.py --from-env NAME` copies it without showing it; if not, the human types it into `<folder>/.env` themselves, saves, and tells you. Check with `skills/synap-core/scripts/check_env.py` (names and lengths only). Placeholders (`add-your-...`) make the first start stop.
6. **Tell the human what the first start does and get a yes:** builds (about 5 to 10 min) or pulls the image, generates the database passwords once, downloads about 2.3 GiB of models once (the machine must not sleep; if the download drops, run `up -d` again and it continues), creates the schema. Then `<compose> up -d > up.log 2>&1 &` from `<folder>`, in the BACKGROUND, and read `up.log` for build errors. `up -d` prints almost nothing until `first-start` finishes; watch with `docker compose -f deploy/docker-compose.yml logs -f first-start` and `... ps`. **Ready** = `synap` is `healthy` and `curl http://127.0.0.1:8000/health` answers `{"status":"ok","edition":"core"}` (503 `not_ready` while models download is normal). `secrets`, `schema` and `first-start` exit 0; that is correct.
7. **While it starts, learn about their agent and write `use-case.md`.** Ask in three short rounds, each question with your recommendation and a tip: (1) what the agent does, who uses it and how often the same person comes back, how they talk to it; (2) three to five real things a user might say and what the agent should remember from each, what it must never forget about a person, what it must never store; (3) anything else (languages, time zones, volume). If there is a project in sight (README, system prompt, tools), read it and propose answers to correct. Write `<folder>/use-case.md` with nine sections: Agent Objective, Target Users, Interaction Pattern, Task Examples (`**User**:` / `**Agent**:` pairs), Behavioral Guidelines, Role Descriptions (from step 4: consumer = the person is both customer and user; business = the organisation is the customer and its people the users), Compliance and Data Sensitivity, Memory Priorities, Additional Context. Only what they said; `not stated` for gaps; never a key or real user data. Run `python3 skills/synap-core/scripts/check_use_case.py`, show the whole file, get a yes.
8. **Ask: design the memory config now, or stay on the starter?** Once healthy. Needs a Synap Cloud account with credits (create one or add credits at https://synap.maximem.ai) and about 20 minutes; recommend yes if they have it. The MACA plugin sends `use-case.md` to Synap Cloud and the finished config comes straight back into `config/memory.generated.yml`; no dashboard step. Commands are in the full skill's `reference/config-and-maca.md` (management key from `maximem-synap auth login`, `scripts/generate_config.py --use-case use-case.md --relationship b2c|b2b`, review, switch to `config/memory.yml`, `scripts/check_config.py`, remove and revoke the key). **Finish before step 9**: verify stores a memory and the scoping mode is final after that. Never start without a yes.
9. **Verify with a real write and recall.** `python3 -m venv .venv && . .venv/bin/activate && pip install maximem-synap` (0.6.13 or newer), `export SYNAP_BASE_URL=http://127.0.0.1:8000` (and `SYNAP_API_TOKEN` if the server has one), then store and read back: `sdk.memories.create(document="User: I prefer dark mode.\nAssistant: Noted!", document_type="ai-chat-conversation", user_id="test_user_check")`, `sdk.memories.wait_for_completion(result.ingestion_id)`, `sdk.user.context.fetch(user_id="test_user_check", search_query=["preferences"])` (pass `customer_id` too on a `strict` install; a customer id is REFUSED on `equals_customer`). Print each `p.content` in `context.preferences`: it returns a short statement about the user, such as "The user prefers dark mode.", not the exact sentence you sent. Better: `python skills/synap-core/scripts/verify_core.py > verify.out 2>&1; echo "exit=$?"` and paste ALL of `verify.out` unedited, `[WARN]` lines included, ending `RESULT:` and `EXIT CODE:`. Never claim success it did not print. Delete your test memories (`sdk.memories.delete(memory_id)`).
10. **Show the human** the memory browser, `http://127.0.0.1:8000/browser/` (read-only; the Config page says "starter config" until `config/memory.yml` is their own), and the commands to keep: `ps`, `logs -f synap`, `stop`, `up -d`, `down` (keeps data; `down -v` deletes it).
11. **Offer, do not start:** a token for the server (`SYNAP_API_TOKEN`); reading `reference/production.md` before exposing it anywhere.
12. **Report** what was done, the verify output, what was skipped and why, and what waits on the human. Wiring memory into an agent framework is the `synap` skill.

## Hard rules

Never print, open or commit a key or token; **never run `git commit`, `git add -A`, `git push`, `git stash` or an amend**; **never `docker compose down -v`, `docker volume rm`, `docker system prune`, `docker volume prune`, delete `originals/`, the Synap Core folder, `.env`, `config/memory*.yml` or `~/.synap`, or change the scoping mode after memories exist, without an explicit yes after listing what is lost**; never overwrite an existing `.env`, `config/memory.yml` or Compose file; if `git pull` conflicts, stop and ask, never stash or reset; deleting a memory does not remove the copy of its text in `originals/`, so never say a person's data is erased; never delete the `state` volume alone (new passwords would not match the old data); touch only Synap Core's own Compose project; do not edit `synap/` or the Compose ports; do not offer Cloud-only features (credits, delete by scope, the live stream `listen()`, a dashboard): Core answers "not available in the open-source server".

## Common failures

`first-start` exits 1: a placeholder is still in `.env`, or the download dropped (run `up -d` again). Port 8000 busy: stop the other stack. `PermissionError ... /app/originals` (Linux): set `SYNAP_USER`, `git pull`. Container exit 137: give Docker more memory. SDK "Connection closed by peer" right after a restart: the server is loading, wait for healthy. "customer_id not accepted": the install is `equals_customer`. A `document` under 100 characters is skipped: use `ai-chat-conversation` for short text. The SDK caches answers for five minutes (`sdk.cache.clear()`). Forget by description needs the human's own `JEV_API_KEY`. More: the full skill's `reference/troubleshooting.md`.
